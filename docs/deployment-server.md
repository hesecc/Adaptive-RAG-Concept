## 页面切换被限流与前端容错发布（2026-11-17 UTC）

当前版本为 `rag-20261117T170022Z`，提交 `be884951e4587293407d149f2977713f56556579`，2026-11-17 17:13 UTC 切换，容器随即健康。起因是线上反馈：点开图片资料库后再点回主页，页面有时只剩背景图，有时回到登录页，隔一会儿刷新又能进入。本版只改静态页面、Nginx vhost 和文档，Python 代码、数据库结构、依赖和 Compose 都没有变化。

根因是网关限流。vhost 里 `an_rag_requests` 区（每个客户端地址 30 次/分钟，突发 10 次）覆盖了 `location /` 下的全部请求，页面外壳、`/static/*`、`/console/session` 和 `/access/domains` 也在其中。应用和 Nginx 都发 `Cache-Control: no-store`，每次切换页面都要把这些重新取一遍：主页约 7 个请求，图片库页约 9 个。几秒内切换两次就超过突发额度，随机一个文件或接口被 429。被拒的是 `app.css` 时，浏览器按 `nosniff` 不应用样式，内联的 Logo `<svg>` 只有 `viewBox`，会铺满窗口，在深色背景上成了一大块黑色，这就是「只剩背景图」。被拒的是 `/console/session`，或者 `domain-controls.js`、`app.js` 没有加载时，旧代码显示登录表单，其中后两种情况还不给出原因。「等一会儿刷新又进去了」符合这个机制：额度每 2 秒补回 1 次。线上 Nginx 错误日志与此吻合：2026-11-17 11:20 至 11:23 UTC 之间，同一个客户端地址有 14 次请求被 `an_rag_requests` 区以 429 拒绝，路径是 `/static/app.js`（4 次）、`/static/domain-controls.js`（3 次）、`/static/app.css`（3 次），以及 `/assets`、`/console/session`、`/static/images.js`、`/access/domains`（各 1 次）。另有一个顺带发现的隐患：登录表单没有 `method`，脚本被拒时浏览器会按 GET 原生提交，口令会出现在地址栏和历史记录里。

网关：新增 `an_rag_pages` 区（300 次/分钟，突发 60），只用于 GET 的页面外壳、`/static/*`、`/console/session` 和 `/access/domains`。这个位置块带 `limit_except GET { deny all; }`，写请求进不了宽松的区。登录、全部写入、`/health`、模型与检索接口，以及 `/documents`、`/assets` 等 JSON 读取仍在原来的严格区，它的速率和突发没有改。应用没有登录失败锁定，严格区是 `/auth/login` 唯一的防暴力破解手段，所以不放宽。已有区的键也没有动：改键后 `nginx -t` 仍通过，但 `nginx -s reload` 会失败，旧配置继续生效（本地用 Nginx 1.30.6 验证过），因此用了新的区名。前端：页面先显示中性的「正在连接工作台…」，只有会话读取返回 401 才显示登录表单；网络错误、429、502、503、504 按 2、4、8 秒重试三次，仍失败就给出原因和一个重新加载链接，其他状态（例如 500）立即报错；`domain-controls.js` 缺失时有明确提示；四个页面的 Logo 带固定宽高，样式表缺失也不会被放大；登录表单改为 `method="post"`；图片库、资料库和评测页遇到 429 显示「请求过于频繁，请稍后重试」。限流说明见 [deploy/README.md](../deploy/README.md) 的「Gateway rate limits」。
