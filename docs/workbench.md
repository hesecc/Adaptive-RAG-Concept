# 检索工作台

工作台由 FastAPI 同源提供，静态文件随 Python 包和 Docker 镜像发布，无独立前端构建服务。视觉参考本机 MotionSites 的 Modern HR Dashboard 资料，使用浅色画布、暖黄色强调色、卡片布局和轻量状态过渡；所有检索状态与运行数据来自后端。

## 连接与运行

1. 启动已配置 HTTP 管理员身份的应用，在浏览器打开该服务根路径 `/`。本地默认地址是 `http://127.0.0.1:8000/`；云部署使用该实例 HTTPS 入口。使用私有 CA 时，应先信任并核对实例的公开 CA。
2. 点击「连接工作台」，输入 `RAG_HTTP_API_TOKEN`。它是本应用独立的 Bearer 令牌；云模型 Key 和 MinerU Key 由服务器管理。
3. 输入问题，选择证据数量；必要时填写 SKU 和历史上下文。点击「开始检索」，或使用 Ctrl / Command + Enter。
4. 在执行链路中选择步骤，查看服务端状态、耗时、开始偏移和结构化返回。查询完成后，切换到回答、证据、模型调用或 JSON 视图。
5. 在证据视图点击「查看原文」，按当前权限重新获取该次引用摘录。截断标记代表查询证据预算产生的截取，回源不会将摘录冒充完整文档。

「本次 Trace ID」位于结果卡标题下方，切换标签页后仍可见；可直接点击「复制 Trace ID」，在「加载 Trace」中回放。执行失败时，页面自动选择失败步骤，显示安全错误说明、实际耗时和已保存的前序步骤输出。失败步骤没有有效返回时会明确说明；它不代表前面的召回结果不存在，也不代表已生成最终回答。正文与输入框使用 15–16px 字号，辅助说明最小 12px。

首个查询前应已通过现有 CLI 或 HTTP 接口导入并发布知识。没有已发布快照时，工作台显示 `no_index`；无模型配置时，仍可执行 BM25 等基座能力，返回证据预览。Laya 保留决策接口，当前继续使用规则策略。

## 数据视图

| 视图 | 显示的数据 |
| --- | --- |
| 执行链路 | 实际阶段顺序、运行/完成/失败状态、服务端耗时、明确的禁用与跳过原因 |
| 步骤详情 | 该步骤记录的结构化返回，例如问题规划、查询变体、召回命中、排序、证据覆盖与核验结果 |
| 回答 | 最终状态、已返回回答、逐条结论与引用，以及尚未覆盖的子问题 |
| 证据 | 文档版本、标题路径、出处、摘录和引用元数据，可再次回源 |
| 模型调用 | 实际请求尝试、模型、接口、耗时、状态与平台返回的 Token 用量 |
| JSON | 本次最终结果与授权 Trace，可下载用于诊断 |

阶段输出是显式业务结果，不包含模型内部推理过程。模型配置关闭时调用数为零；平台未返回的用量不补造。运行中的页面等待耗时来自浏览器计时，结束后切换为服务端 Trace 耗时；两者测量范围不同。服务端阶段耗时与总耗时也包含各自测量范围，不应假定所有阶段之和等于端到端网络时间。

## HTTP 事件契约

`POST /query/stream` 接受与 `POST /query` 相同的严格 JSON 输入，并要求管理员 Bearer 身份。浏览器使用 `fetch` 读取 SSE，以便通过 `Authorization` 请求头鉴权，不将令牌放在 URL 中。

```json
{
  "question": "Transformer 的注意力机制如何工作？",
  "top_k": 5,
  "history": []
}
```

| 事件 | 数据 | 发生时间 |
| --- | --- | --- |
| `trace` | `trace_id` | 本次执行开始 |
| `stage` | 阶段索引、名称、状态、开始偏移与已完成耗时等元数据 | 对应阶段实际开始或结束 |
| `result` | `result` 与 `trace` | 查询完成、Trace 持久化且当前权限检查通过后 |
| `error` | 安全的错误代码、说明、`error` 诊断对象、可用的 `trace_id`；权限复核通过且记录可读时附带 `trace` | 流式响应开始后的执行失败 |

身份和输入校验失败可在建立事件流之前返回常规 HTTP 错误。事件流建立后，HTTP 200 只表示连接已建立；调用方必须等到 `result`，或处理 `error` 与提前断开。前端不会因连接错误自动重复提交付费查询。

失败事件中的 `trace` 通过与历史回放相同的当前权限检查。旧服务未附带 Trace 或流连接提前断开时，页面至多尝试一次只读 `GET /traces/{id}` 恢复记录。模型调用记录可包含固定白名单中的 `error_code` 与网络/超时异常类别 `error_type`，不保存上游异常正文、请求头或密钥。网络与超时错误不自动重试；旧记录未保存具体异常类别时，页面只说明可证实的失败原因。

主动取消的记录使用独立的 `query_cancelled` 诊断，历史回放也显示取消原因。若查询已完成、仅终态记录读取临时失败，恢复的 Trace 含 `final_result` 时按已保存的最终结果显示回答与证据。

`GET /console/session` 验证管理员身份并读取当前插件配置。`GET /traces/{id}` 读取同租户历史 Trace，并按当前访问权限检查其中的源内容。旧 Trace 未记录的步骤输出或最终回答明确显示缺失，不伪造回放数据。

## 会话与权限

- 页面和静态资源可公开加载，业务数据始终通过 Bearer 鉴权。当前工作台要求管理员身份，并沿用服务器中令牌到身份、租户和权限的可信映射。
- 令牌只在页面内存保存，不写入 localStorage、sessionStorage、Cookie 或下载文件。刷新页面、关闭标签页或断开连接后需重新连接。
- 本次会话记录只在当前页面保留。点击「清空」清除查询与结果；历史 Trace 仍按服务器的持久化策略保存，可凭 ID 再次读取。
- 实时阶段只发送状态和耗时等元数据。终态内容展示前执行权限复核，历史 Trace 与证据回源也检查当前权限；撤权不能远程收回浏览器已经接收或用户已经下载的内容。
- 文档、问题、生成文本及结构化数据均以文本节点呈现，不执行其中的 HTML 或脚本。
- 「停止本次查询」中止浏览器请求并取消服务端协作式查询。同步线程或不协作的插件仍受现有超时限制，不能将取消描述成进程级强制终止。

## 部署

静态文件位于 `adaptive_rag/static/`，由 setuptools package-data 纳入发行包。现有 Dockerfile 复制整个 `adaptive_rag` 包，因此无需 Node 运行时、额外容器或新增中间件。发布工具的运行文件白名单必须包含这四类静态资源：HTML、CSS、JavaScript、SVG。

HTTPS 代理需要允许 `/`、`/static/*`、`/console/session` 与 `/query/stream` 访问同一个应用，转发 `Authorization`，并关闭 SSE 代理缓冲。该服务器现有独立 Nginx 入口已关闭代理缓冲；发布后仍需验收严格 TLS、静态资源加载、实时阶段事件、最终结果和回源权限。页面内容安全策略与响应头由应用提供，不能以代理上线代替浏览器验收。
